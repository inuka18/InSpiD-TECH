# Requirements network evaluation

Generated by `npm run network:evaluate` on database `inspid_test` with the MiniLM embeddings from the ai-service. The key is `network_ground_truth` (scenario_related_pairs.csv: `same_group` and `dependency` pairs) plus each requirement's `group_id`.

**Small data warning:** there are only 4 projects with 23 to 34 requirements each (114 in total, 28 ground-truth groups of 2 to 6 members). Differences of a few points are noise, and per-project numbers rest on very few items.

**What was tuned on the ground truth:** nothing in the app. The number of clusters is k = clamp(round(sqrt(n)), 3, 8) per project (5, 5, 6, 6 here), **chosen for usability in the UI and not tuned on `group_id`** (or on any other data), so its scores below are not inflated by tuning. The old distance-cutoff clustering is kept only for comparison: its single number (the cutoff) was chosen as the value in 0.30..0.90 (step 0.02) with the highest mean adjusted Rand index (ARI) against `group_id`, and it is no longer used by the app. The embedding model, the Pathfinder rule and the baselines use no ground truth.

## How to read these numbers

- **Neighbours:** MiniLM finds a same-group requirement as the nearest neighbour 43.9% of the time (TF-IDF 33.3%, random 12.6%), and within the top 3 71.1% (TF-IDF 58.8%, random 33.6%). That is well above random and above TF-IDF overall, but the per-project gaps to TF-IDF are inconsistent (TF-IDF is ahead at hit@1 in some projects), so with 114 requirements this is weak evidence of a real advantage.
- **Edges:** Pathfinder removes 93.1% of the possible pairs. Its edge precision (47.3%) is only 3.6 points from the plain similarity graph with the same number of edges (43.6%); that difference is inside the noise. Its benefit here is the large reduction in edges, not higher precision.
- **Groups vs text:** Pathfinder on a complete graph yields about n - 1 edges, i.e. a spanning structure, so it cannot connect every group internally. Only 21.4% of the ground-truth groups are connected inside the group.
- **Clusters:** the app's k-based clustering gives 22 clusters over 114 requirements (average size 5.2) with mean ARI 0.113 and NMI 0.409. The old cutoff version gave 52 clusters (average size 2.2) with in-sample ARI 0.214 and leave-one-project-out ARI 0.191. Compare ARI/NMI only as agreement with the key: fewer, bigger clusters can raise or lower them for reasons unrelated to usefulness, and the differences are small relative to the noise of 4 projects.
- **Why the key may be a poor yardstick:** `group_id` is the scenario author's business grouping, not a similarity-by-wording grouping. In SYS-RET, for example, the group "Customer Accounts" contains Social account sign-in, Returns and refunds, and Wishlist. A text-based network cannot be expected to reproduce such groups, so these scores measure agreement with the key, not the usefulness of the network.
